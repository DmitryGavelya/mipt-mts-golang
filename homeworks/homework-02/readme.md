## Задача

Герой сражается с волной врагов подряд, один за другим: без карты и
комнат, просто очередь противников. Партия заканчивается смертью
героя (`HP <= 0`) или победой над всей волной.

Игра управляется двумя неэкспортируемыми функциями. `initGame`
инициализирует фиксированный сценарий (числа ниже — как есть).
`handleCommand` принимает команду и возвращает текстовый ответ — это
единственный способ взаимодействия с игрой. Больше контракт ничего
не фиксирует: реализацию героя, врагов, предметов и инвентаря вы
выбираете сами. `main_test.go` редактировать нельзя — он сверяет
ответы посимвольно, это и есть протокол.

Стартовый сценарий:

- герой: HP 20/20, атака 10, инвентарь — зелье x1, меч x1;
- волна врагов по порядку: goblin (HP 8/8, атака 3), skeleton (HP 10/10, атака 2), goblin (HP 15/15, атака 4).

## Что нужно сделать

1. Реализуйте `initGame()` и `handleCommand(command string) string` в `main.go`.
2. Поддержите команды из тестов: `атаковать`, `дальше`, `использовать <предмет>`, `статус`.
3. Реализуйте предметы полиморфно (минимум 2 вида):
   - зелье — `+20` HP, но не выше `MaxHP`;
   - меч — разово `+5` к атаке на всю игру, сам предмет расходуется.

   Использование предмета не тратит ход: враг не отвечает.

4. Реализуйте врагов с общей частью через embedding (минимум 2 типа):
   - goblin — без особенностей;
   - skeleton — при первой смертельной атаке вместо смерти воскресает с `HP = MaxHP / 2`; второй смертельный удар убивает окончательно.
5. Реализуйте раунд боя: сначала бьёт герой; если противник жив
   (включая воскрешение скелета) — отвечает уроном; если противник
   окончательно повержен — ответного удара нет.
6. Переход `дальше` разрешён только после победы над текущим
   противником; пока он жив — команда отклоняется.
7. Обеспечьте инвариант: любое недопустимое в текущем состоянии
   действие возвращает сообщение об отказе и не меняет состояние.
8. Прогоните тесты:

   ```
   go test -v
   ```

   Ожидаемый результат: все тесты `PASS`, `main_test.go` не изменён.

## Важные ограничения

- `main_test.go` изменять нельзя — сверка ответов идёт по точной строке.
- Недопустимое действие не должно менять состояние игры: воскрешение
  скелета тесты проверяют по двум конкретным ударам, а не по факту
  «дошла ли партия до конца».
- Никаких экспортируемых типов или функций сверх контракта тесты не
  ожидают.

## Критерии проверки

Задание принимается, если:

- `go test -v` в папке `homework-02` проходит полностью, `main_test.go` не тронут;
- happy path проходит волну до «Победа!»;
- зелье и меч работают полиморфно, зелье не превышает `MaxHP`, меч даёт `+5` разово;
- skeleton воскресает ровно один раз, затем гибнет окончательно;
- `дальше` отклоняется при живом противнике и после конца волны;
- `атака`, `использовать` и неизвестная команда в недопустимом состоянии не меняют состояние игры;
- код собирается, `go vet ./...` без замечаний.

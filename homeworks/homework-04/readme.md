## Задача

API управления задачами (CRUD). Всё хранится в памяти, но периодически сбрасывается в JSON-файл.

### Endpoints

| Method | Path | Описание |
| :---- | :---- | :---- |
| POST | /v1/tasks | Создать задачу |
| GET | /v1/tasks | Список задач |
| GET | /v1/tasks/{id} | Получить задачу |
| PUT | /v1/tasks/{id} | Обновить задачу |
| DELETE | /v1/tasks/{id} | Удалить задачу |
| GET | /v2/tasks/{id} | Получить задачу в расширенном формате |

### Требования

1. **Хранилище в памяти.** `TaskStore` — потокобезопасное хранилище в памяти. ID генерируется автоматически при создании. Поле `CreatedAt` заполняется при создании, `UpdatedAt` — при создании и обновлении.

2. **Graceful shutdown.** В `main()` сервер должен корректно завершаться при `SIGTERM`/`SIGINT`: перестать принимать новые запросы, дождаться завершения активных запросов (до `ShutdownTimeout`), затем выйти.

3. **Rate limiting.** Собственная реализация token bucket. Лимит: 10 запросов в секунду на IP. Bucket должен создаваться отдельно для каждого IP-адреса. Если лимит превышен — возвращать `429 Too Many Requests`.

4. **Middleware-цепочка.** Применяется в следующем порядке (внешний → внутренний):
   - `LoggingMiddleware` — логирует метод, путь, статус и длительность запроса;
   - `RateLimitMiddleware(RateLimitRPS, RateLimitBurst)` — rate limit по IP;
   - `RecoveryMiddleware` — ловит panic в любом handler'е, возвращает `500 Internal Server Error`;
   - `AuthMiddleware` — проверяет заголовок `X-Auth-Token: bearer-token`, без токена или с неправильным токеном — `401 Unauthorized`.

   Собирается через `Chain(...)`.

5. **Версионирование API.** `/v1/tasks` работает с базовым JSON-форматом (`Task`). `/v2/tasks/{id}` возвращает расширенный формат (`TaskV2Response`), который включает метаданные: `version: "v2"` и `total_tasks` (общее количество задач в хранилище).

6. **Периодический сброс в JSON.** Каждые `SaveInterval` (5 секунд) все задачи сбрасываются в `TasksFileName` (`tasks_backup.json`). При завершении программы должен быть выполнен финальный сброс.

### Важные ограничения

* `main_test.go` изменять нельзя — он проверяет корректность CRUD, middleware, rate limiting, версионирования и периодического сохранения.
* `common.go` изменять нельзя — типы и константы даны.
* Никаких внешних зависимостей для роутинга (`chi`, `gorilla/mux` и т.д.) — используйте стандартный `net/http`.
* `time.Sleep` в бизнес-логике не нужен — используйте его только в token bucket (если требуется для тестов).
* При обновлении несуществующей задачи возвращайте `404 Not Found`. При получении несуществующей — тоже `404`.
* При удалении несуществующей задачи возвращайте `404`.
* Все операции с `TaskStore` должны быть потокобезопасными — тесты проверяются с `-race`.

### Подсказки

* Сигнатуры не даны специально — смотрите, как `main_test.go` вызывает функции, и исходя из этого восстанавливайте их имена, аргументы и возвращаемые значения.
* Для graceful shutdown используйте `http.Server.Shutdown` с `context.WithTimeout`.
* Token bucket: храните `tokens` (float64), `last` (time.Time), `rate` и `burst`. В `Allow()` вычисляйте, сколько токенов накопилось с момента `last`, не превышая `burst`.
* Для rate limit по IP используйте `map[string]*TokenBucket` с `sync.Mutex` или `sync.RWMutex`.
* `Chain` работает как матрёшка: `m1(m2(m3(handler)))`.
* `httptest.NewServer` и `httptest.NewRecorder` — ваши друзья для тестирования HTTP-обработчиков.
* Логирование можно делать через стандартный `log` или `fmt`, главное — логировать метод, путь, статус и длительность.
* Для получения IP из запроса используйте `req.RemoteAddr` (в тестах его можно подменить через `httptest.NewRequest(...).RemoteAddr = "..."`).
* При graceful shutdown используйте `signal.Notify` для `syscall.SIGTERM` и `syscall.SIGINT`.
